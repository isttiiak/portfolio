# istiak.dev — Portfolio

Personal portfolio of **Istiak Islam** — software engineer & data engineer.
Live: [isttiiak.vercel.app](https://isttiiak.vercel.app)

**Stack:** Next.js (App Router) · TypeScript · Tailwind CSS v4 · Framer Motion · GSAP · Lenis · MDX

---

## Quick reference — where everything lives

| I want to change… | Edit this file |
|---|---|
| Name, roles, email, links, tagline | `lib/data/site.ts` |
| Project cards on the home page | `lib/data/projects.ts` |
| About-section bio paragraphs | `components/sections/About.tsx` |
| Stat counters (3 products, 77 repos…) | `lib/data/timeline.ts` (bottom) |
| Journey timeline entries | `lib/data/timeline.ts` |
| Skills grid + marquee | `lib/data/skills.ts` |
| A case-study page | `content/projects/<slug>.mdx` |
| A blog post | `content/blog/<slug>.mdx` |
| **CV content (both versions)** | **`cv/src/body.tex`** — then run `make` in `cv/` |
| Resume PDF on the site | auto-generated by `make` in `cv/` (or replace `public/istiak-islam-resume.pdf`) |

After any edit: commit + push to `main` → Vercel deploys automatically in ~1 minute.

```bash
git add -A
git commit -m "add new project"
git push
```

No local setup? Open the repo on GitHub and press `.` (period) — that opens **github.dev**, a browser VS Code where you can edit any file and commit. Perfect for MDX edits.

## How-to with examples

### 1. Update personal info

Edit `lib/data/site.ts`. Everything here flows to the hero, navbar, contact section, footer, and SEO metadata:

```ts
export const site = {
  name: "Istiak Islam",
  roles: ["Software Engineer", "Data Engineer"],   // hero typewriter cycles these
  tagline: "I build full-stack products and end-to-end data pipelines…",
  url: "https://isttiiak.vercel.app",              // change when you get a custom domain
  email: "isttiiak@gmail.com",
  telegram: "https://t.me/mobs08",
  // …
} as const;
```

### 2. Add a new project card (home page)

Open `lib/data/projects.ts` and add an object to the `projects` array:

```ts
{
  slug: "my-new-app",              // unique, used in URLs
  title: "My New App",
  kind: "software",                // "software" or "data" — data ones also appear in section 03
  summary: "One or two sentences shown on the card.",
  tags: ["Next.js", "PostgreSQL", "Docker"],
  live: "https://my-new-app.vercel.app",   // optional — shows the pulsing LIVE badge
  github: "https://github.com/isttiiak/my-new-app",
  caseStudy: false,                // set true ONLY after you create the .mdx (step 3)
  metrics: [                       // optional — the highlighted numbers on the card
    { value: "1.2K", label: "users" },
    { value: "99.9%", label: "uptime" },
  ],
  year: "2026",
},
```

To show it in the **featured horizontal gallery**, add its slug to `featuredProjects` at the bottom of the same file:

```ts
export const featuredProjects = projects.filter((p) =>
  ["fintrack", "mercari-price-suggestion", "ihsan", "my-new-app"].includes(p.slug)
);
```

`kind: "data"` projects automatically appear in the Data & ML section — nothing else to do.

### 3. Add a case-study page for a project

Create `content/projects/my-new-app.mdx` (filename = the slug from step 2). The page appears at `/projects/my-new-app` automatically:

```mdx
---
title: "My New App"
description: "One-line description shown under the page title and in SEO."
year: "2026"
role: "Solo developer"
stack: ["Next.js", "PostgreSQL", "Docker"]
live: "https://my-new-app.vercel.app"
github: "https://github.com/isttiiak/my-new-app"
order: 5
---
```

## Editing the CV (LaTeX)

**Only edit `cv/src/body.tex`.** The other two `.tex` files are tiny wrappers that switch the photo on/off — never touch them for content.

```
cv/
├── src/body.tex               ← ALL content lives here (edit this)
├── istiak-islam-cv.tex        ← wrapper: no-photo version (don't edit)
├── istiak-islam-cv-photo.tex  ← wrapper: photo version (don't edit)
├── photo/istiak.jpg           ← swap this file to change the photo
├── Makefile
├── istiak-islam-cv.pdf        ← output (ATS version)
└── istiak-islam-cv-photo.pdf  ← output
```

### The exact commands after editing `cv/src/body.tex`

```bash
cd /Users/istiakislam/projects/myportfolio/cv
make
```

That one `make` command does three things: compiles the no-photo PDF, compiles the photo
PDF, and copies the no-photo version to `public/istiak-islam-resume.pdf` so the website
serves the fresh copy. Then to put it on the live site:

```bash
cd ..
git add -A && git commit -m "update cv" && git push
```

If `make` ever fails, the error names a line number — it's almost always an unescaped
`%`, `$`, or `&` (write `\%`, `\$`, `\&`).

Common edits inside `body.tex`:

```latex
% A project entry looks like this — copy the block to add one:
\entry{Project Name — Short Descriptor}{2026}
\subentry{Tech, stack, list \;·\; \href{https://github.com/...}{GitHub}}{Right-side label}
\begin{itemize}
  \item Achievement with a \textbf{bold metric}
  \item Escape these characters: \% \$ \& \# (percent, dollar, ampersand, hash)
\end{itemize}
```

LaTeX gotchas: `%` starts a comment (write `\%`), `$` starts math mode (write `\$`), `&` breaks lines (write `\&`). If `make` fails, the error message names the line number — check for an unescaped character there. No LaTeX installed on another machine? Upload the `cv/` folder to [overleaf.com](https://overleaf.com) (free) and compile there.

## Deploy & services

- **Hosting:** Vercel auto-deploys every push to `main`. Nothing to do.
- **Contact form:** needs a free key from [web3forms.com](https://web3forms.com) → add `NEXT_PUBLIC_WEB3FORMS_KEY` in Vercel → Settings → Environment Variables → redeploy. Without it, the form falls back to opening the visitor's mail app (mailto) — nothing breaks.
- **Custom domain later:** Vercel → Settings → Domains → add it, then update `url` in `lib/data/site.ts` so sitemap/OG cards point at it. Free option: claim `istiak.is-a.dev` via a PR at [github.com/is-a-dev/register](https://github.com/is-a-dev/register).
- **GitHub calendar:** reads the public API for `isttiiak` — no token, no setup.

## Notes

- `myinfo/` (raw CVs, photos) and `cv/build/` are gitignored.
- All animations respect `prefers-reduced-motion`; cursor + particle canvas are disabled on touch devices.
- Run `npm run build` before pushing structural changes — MDX frontmatter typos surface at build time, not runtime.
